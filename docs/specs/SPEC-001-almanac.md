# SPEC-001 万年历

> 状态：`Implemented Baseline / UI Review`  
> 版本：0.9  
> 最近更新：2026-08-07  
> 依赖：[规则来源登记表](../rules/source-register.md)、[cnlunar 技术基线](../rules/cnlunar-adoption.md)、SPEC-007

## 1. 目的

提供可浏览的日历和稳定的历法上下文，使用户既能独立查看日期信息，也能把明确的日期、时间和时区带入六爻排盘。

## 2. 范围内

- 公历月视图、上月/下月切换、返回今天。
- 日期选择和日详情。
- 公历、农历、生肖、节气、四柱、四柱纳音、时辰干支和财神方位；其余首版字段仍待规则评审。
- 明确显示排盘采用的时间、时区和换日口径。
- 从选中日期发起排卦。
- 值日二十八宿作为万年历 provider 字段进入首版；它与六爻逐爻装宿分开建模。

## 3. 范围外

- 六爻的五星二十八宿入卦算法，由 SPEC-008 管理。
- 起卦和排盘，由 SPEC-002、SPEC-003 管理。
- 日程管理、提醒、节日内容运营、黄历文章。
- 未确认来源的宜忌、吉凶评分和个性化推荐。

### 3.1 当前实现基线

- 生产计算位于纯 Dart `liuyao_engine`，App 不经 HTTP 调用 Python cnlunar。
- cnlunar 原始农历月数据和节气压缩数据已冻结，支持区间为 1901-02-19 至 2100-02-08。
- 内置 Asia/Shanghai 1901–2100 offset 变更，设备时区不改变排盘墙上时间。
- 完整 Python 对照矩阵 16,115/16,115 通过，覆盖春节、24 节气、普通日及 22:30/23:30。
- 已加入 cnlunar 值日二十八宿；排盘中的京房逐爻二十八宿仍由 SPEC-008 管理。

## 4. 首版页面结构

1. 月历顶栏：年月、切月、回到今天。
2. 日期网格：公历日为主，农历/节气为副。
3. 选中日摘要：公历、农历、干支、节气。
4. 日详情：按“历法 / 干支 / 节气 / 其他已启用字段”分组。
5. 主操作：“以此时间起卦”。

### 4.1 UI 参考基线

参考证据：[LG-20260805-01](../assets/ui-reference/calendar-month-2026-08.jpg) 和 [LG-20260805-02](../assets/ui-reference/chart-calendar-linked-2026-08.jpg)。采用其“七列月历 + 选中日下方连续详情”的信息结构，不复制品牌资产或未经确认的历法字段。

- 月份标题突出显示，提供年月选择和前后月切换。
- 日期格采用公历日、农历日/节气、日干支三层候选结构。
- 非本月日期降级显示；选中日使用高对比容器；今日另有独立标识。
- 月历下方按卡片分组展示当日信息，允许整页纵向滚动。
- 卦面需要访问日期上下文时，优先复用同一个日期详情组件或跳转入口；是否嵌入完整月历待线框评审。
- 已确认四柱、纳音、时辰干支和财神方位进入首版。
- 截图中的喜神、福神、阳贵、阴贵等其他方位仍是候选，不因截图出现而自动纳入。

## 5. 关键要求

- `FR-ALM-001` 月历必须清楚区分今天、选中日、非本月日期。
- `FR-ALM-002` 用户选择日期后，可指定具体时分；未指定时不得假装已有准确时柱。
- `FR-ALM-003` 所有派生历法字段必须携带算法/数据源版本。
- `FR-ALM-004` 从日历进入起卦时，传递的是标准化时间对象，不是格式化字符串。
- `FR-ALM-005` 对子初换日、立春换年、节气换月等口径必须在规则文档中冻结。
- `FR-ALM-006` 无法计算的字段显示“未计算/资料未启用”，不显示占位结论。
- `FR-ALM-007` 日期格在 360dp 宽度下仍能显示公历日及至少一行历法副文，不发生水平滚动。
- `FR-ALM-008` 选中日、今日、节气、非本月日期必须使用可区分且不只依赖颜色的状态表达。
- `FR-ALM-009` 选中日期后，日详情在同一页面更新；用户的月视图滚动和选中状态应保持。
- `FR-ALM-010` 月历与卦面引用同一标准化时间对象，任何一处修改日期都必须按明确交互同步或生成新版本。
- `FR-ALM-011` 日详情展示所选时间的年柱、月柱、日柱和时柱，并清楚标注四柱顺序。
- `FR-ALM-012` 每一柱的纳音必须与对应干支成组展示和保存，不能只拼接为一段无结构文本。
- `FR-ALM-013` 日详情展示所选时刻的时辰干支，并允许查看当日各时辰对应的干支；切换时辰后同步更新时柱与依赖字段。
- `FR-ALM-014` 日详情展示财神方位，并保存采用的取法、结果方向和规则版本。
- `FR-ALM-015` 万年历计算通过项目自有适配层调用 cnlunar，API 不得直接暴露第三方 `Lunar` 对象或未解析中文字符串。
- `FR-ALM-016` 每次结果保存 `source=cnlunar`、精确依赖版本/提交、适配器版本和规则选项。
- `FR-ALM-017` cnlunar 适配器的安全本地日期范围固定为 1901-02-19 至 2100-02-08；超出范围返回明确的 422，不调用上游产生不确定结果。
- `FR-ALM-018` 月视图接口固定返回周一开头的 6 行 × 7 列共 42 个日期格，并包含相邻月份日期。
- `FR-ALM-019` 每个可用日期格至少返回公历日期、是否本月、农历月日、日干支和当日节气。
- `FR-ALM-020` 月份首尾网格超出安全日期范围时保留日期格并标记 `available=false`；请求月份完全不与支持范围重叠时返回 422。
- `FR-ALM-021` Flutter 只调用纯 Dart `liuyao_engine` 的公开合同；生产代码不得调用 Node/Python 服务，也不得维护第二套历法计算。
- `FR-ALM-022` 年柱必须在立春精确时刻切换，月柱必须在十二“节”的精确时刻切换；不得只按交节日期零点切换。
- `FR-ALM-023` 日柱和六神日干采用 cnlunar 兼容的 23:00 子初换日；规则元数据必须与真实行为一致。
- `FR-ALM-024` 值日宿必须保存为 provider 扩展，不得覆盖 SPEC-008 的逐爻宿字段。

## 6. 数据边界

输入至少包含：本地日期时间、IANA 时区、可选地点。输出应区分：原始输入、标准时间、农历字段、四柱结构、逐柱纳音、时辰干支选项、财神方位、节气字段、值日宿字段和规则版本。

经度、真太阳时、早晚子时是否进入首版仍待决定。未决定前不可让 UI 暗示已采用。

### 6.1 技术基线

- 计算基础：[OPN48/cnlunar](https://github.com/OPN48/cnlunar)。
- 运行位置：纯 Dart `packages/liuyao_engine`；Python 仅作为开发期对照。
- 封装边界：`liuyao_engine` 输出本项目稳定 Map/JSON 合同，Flutter 只消费公开 API；Python `AlmanacAdapter` 只用于对照。
- 版本策略：正式开发时固定 tag 或 commit，升级前运行完整 golden tests。
- 许可：生产移植锚定上游 MIT commit `8a944ad...`，发布物保留版权和许可声明；`v0.2.0` 标签本身是 GPLv3，不混写。
- 二十八宿限制：上游提供值日宿不代表启用六爻入卦；仍服从 SPEC-008。

## 7. 验收重点

- 固定 10 个跨节气、跨年、闰月和子时样例，与权威来源逐字段比对。
- 从日历进入起卦后，时间和时区不丢失。
- 历法数据源升级不会静默改变已保存案例。
- 四柱与四组纳音在 UI、持久化和导出中保持逐柱对应。
- 切换时辰后，时柱及依赖时柱的结果同步变化，年/月/日柱保持不变。
- 财神方位结果能显示来源规则和计算版本。

## 8. 当前实现状态

### 已实现

- [纯 Dart 万年历](../../packages/liuyao_engine/lib/src/almanac.dart)：历史时区转换、23:00 日界、精确交节四柱、农历、逐柱纳音、13 个时辰干支槽、值日宿、节气、财神与 calculation trace。

- [Flutter 万年历模型与客户端](../../apps/mobile/lib/src/features/almanac/)：直接调用本地轮子，生成 42 格月历和日详情，不发起 HTTP。
- [Flutter 万年历页面](../../apps/mobile/lib/src/features/almanac/almanac_page.dart)：完成固定月格、前后月/回今天、选日、四柱逐柱纳音、时辰切换、财神方位，以及加载与错误状态。
- [Flutter 组件测试](../../apps/mobile/test/widget_test.dart)：覆盖 360dp 月历/日详情、切月/选日/切时辰和四段一级导航。
- `cnlunar==0.2.0` 已固定在 Python 项目依赖。
- Python 测试继续验证对照实现；`scripts/check_offline_almanac_parity.py` 完整核对 16,115 个边界快照。

### 当前本地调用输入

```json
{
  "timestamp": "2026-08-05T07:25:00Z",
  "timezone": "Asia/Shanghai",
  "year_boundary": "lunar_new_year"
}
```

`year_boundary` 同时支持 `beginning_of_spring`，但产品默认口径仍需通过 Q-003 最终确认。
