# SPEC-004 五行十二长生与神煞标注

> 状态：`In Progress`  
> 版本：1.2  
> 最近更新：2026-08-07  
> 依赖：[六爻规则与实施路线](../liuyao-rule-roadmap.md)、[规则来源与实现状态审计](../rules/spec-004-source-audit.md)、SPEC-003

## 1. 目的

在基础卦面之上，以独立、可开关、可追溯的规则模块标注五行十二长生和指定神煞，不把多流派差异埋进 UI 或单一结论。

## 2. 范围内

### 五行十二长生

已采用“五行十二长生”；不是十天干阴阳顺逆十二长生。schema v14 起木、火、金、水按五行表，土按辰、戌、丑、未四土本气分别查询。历史“土水同表、统一顺行”只属于旧 v1 快照，不再用于新盘。

十二阶段：长生、沐浴、冠带、临官、帝旺、衰、病、死、墓、绝、胎、养。

schema v16 对本卦、完整伏卦、变卦三层六爻分别计算年、月、日、时四个参照结果；四柱必须来自项目 cnlunar 时间权威链。静卦不生成变卦层。

### 当前产品标注范围

当前新盘固定输出五项神煞：驿马、桃花、禄神、华盖、天乙贵人；同时输出两项辅助结构：卦身、命爻。顺序固定为“驿马、桃花、禄神、华盖、天乙贵人、卦身、命爻”。

“卦身”的规范名固定为“月卦身”：由世爻阴阳和世位取目标支，并标记本卦所有同支明爻；命爻由世爻支按选定版本表取绝对爻位。二者只保存机械位置，不自动解释吉凶。将星、世身及旧 20 项目录其余名称保留在历史快照或研究台账，不进入 schema v15 新盘输出；私有参考合同仍原样保存其候选数据。

## 3. 范围外

- 二十八宿与五星入卦，由 SPEC-008 负责。
- 自动解读神煞含义、吉凶评分和组合断语。
- 未经确认自动把用户用词替换为别名。

## 4. 命名待确认

当前研究文档中仍存在可能的规范化候选：金鱼/金舆、鸿雁/红艳、香归/香闺。挂身/卦身已由 DEC-049 对当前产品解决：显示名“卦身”，规范名“月卦身”；不等同于世身。正式数据字典继续支持“显示名、规范名、别名、规则版本”。

## 5. 展示分层

- **逐爻字段**：能明确落到某一爻支或某一爻五行的标注。
- **卦级命中**：由日支、年支或卦象推导，但不属于单一爻的标注。
- **辅助结构**：卦身、世身等结构定位，不应与神煞混成同一计算类型。
- **解释层**：含义说明独立于“是否命中”的确定性结果。

## 6. 关键要求

- `FR-ANN-001` 每个规则独立注册，包含规则 ID、版本、输入域、查表/公式、结果域和来源。
- `FR-ANN-002` 每次命中记录触发依据，例如“日支申 → 驿马寅 → 三爻地支寅命中”。
- `FR-ANN-003` 未计算、未命中、不适用、规则有争议必须是不同状态。
- `FR-ANN-004` 用户可以按规则组显示/隐藏，不能影响基础卦面结果。
- `FR-ANN-005` 同名但不同取法的规则不得共用一个无版本标识的结果字段。
- `FR-ANN-006` 每项规则至少需要命中、未命中和边界样例。
- `FR-ANN-007` 十二长生 v1 必须输出 5×12 完整表、六爻×四柱共 24 个结果，不允许只在 UI 临时计算。
- `FR-ANN-008` 十二长生阶段“沐浴”与独立“沐浴杀”使用不同规则 ID；未决定独立规则前不得互相替代。
- `FR-ANN-009` 禄神 v1 固定以项目日干查表，并只扫描本卦明爻；伏神、变爻必须以 `excluded_scopes` 明示，不能静默忽略。
- `FR-ANN-010` 神煞结果必须区分 `computed_match` 与 `computed_no_match`；即使盘内未现目标支，也必须保存完整计算结果。
- `FR-ANN-011` 天乙 v1 必须为每个日干保留两个目标支的口诀顺序，并返回两个目标下的全部明爻命中，不能找到第一处后提前结束。
- `FR-ANN-012` 驿马 v1 必须只以项目日支查四组三合表，不读取年支且不年日并算；本卦明爻未现目标支时仍必须保存 `computed_no_match`。
- `FR-ANN-013` 桃花 v1 的显示名固定为“桃花”、规范名为“咸池”，只以项目日支查四组三合表；月支、年支及组合取法不得静默进入结果。
- `FR-ANN-014` 将星 v1 必须只以项目日支查四组三合表；出师章的农历月序将星必须使用独立规则 ID，不能与日支结果合并或覆盖。
- `FR-ANN-015` 华盖 v1 必须只以项目日支查四组三合表，并包含处于动爻状态的本卦明爻；农历月序华盖必须使用独立规则 ID，变卦对应爻不得参与匹配。
- `FR-ANN-016` 土十二长生必须输出实际采用的四土本气和阶段表；不得以一个无版本的“土”结果掩盖辰戌丑未差异。
- `FR-ANN-017` 私有参考神煞候选与产品逐爻命中标注分字段保存；候选不自动等同于明爻命中或吉凶结论。
- `FR-ANN-018` schema v15 的 `annotations.shensha.results[]` 只输出驿马、桃花、禄神、华盖、天乙贵人并保持该顺序；将星不得进入新结果，历史快照不得被改写删除。
- `FR-ANN-019` `annotations.body_markers` 必须独立保存卦身和命爻。卦身显示名为“卦身”、规范名为“月卦身”，保存目标支、全部匹配爻及未上卦状态；命爻保存所选异法 ID、绝对爻位和对应爻数据。
- `FR-ANN-020` 卦身和命爻可与神煞在同一 UI 卡片连续展示，但数据分类、规则 ID 和计算轨迹必须独立，不作吉凶评分。
- `FR-ANN-021` `annotations.hexagram_layers` 必须分别保存本卦、伏卦、变卦的十二长生结果；每层以该层六爻地支为主体，不能把本卦阶段复制给伏卦或变卦。

- 每爻结果：`line_id`、爻位、爻五行、四条 `pillar_results`。

## 8. 验收重点

- 五行十二长生的 5×12 映射完整、可逆向检查。
- 20 个用户指定名称均有状态：已确认规则、待确认取法或待确认名称，不得遗漏。
- 规则切换或升级不会影响基础排盘。
- 计算明细中能看到所有参与运算的输入、中间值和匹配结果。
- 固定例 2026-08-05 15:26、初爻水的年/月/日/时结果必须为胎/养/临官/长生。
- 同一固定例为辛亥日，禄神目标支必须为酉，并命中 `base-5`；另有无酉支样例证明 `computed_no_match` 不被省略。
- 同一固定例的天乙目标必须为午、寅，并命中 `base-2`；测试必须覆盖双目标、多命中和完全未命中。
- 同一固定例的驿马必须以亥日取巳，并返回 `computed_no_match`；二爻伏神乙巳不得误算为明爻命中。
- 同一固定例的桃花必须以亥日取子，并命中 `base-1`；测试必须覆盖同支多爻、完全未命中、伏神排除和非法日支。
- 历史将星规则继续通过原有独立测试，但 schema v15 新盘的 `shensha.results` 不得出现将星。
- 同一固定例的华盖必须以亥日取未并命中处于动爻状态的 `base-6`；2026-08-06 火天大有必须以子日取辰、只命中 `base-3`，不得误用农历六月月序取未命中 `base-5`。
- 2026-08-04 22:22:29 山天大畜三爻动固定例中，卦身规范名为月卦身、目标支为丑，命爻位于上爻；结果必须带完整 trace，不输出吉凶。
