# SPEC-002 六爻起卦模式

> 状态：`Implemented Baseline / UI Review`  
> 版本：1.0  
> 最近更新：2026-08-06  
> 依赖：SPEC-001、[六爻规则与实施路线](../liuyao-rule-roadmap.md)

## 1. 目的

让用户通过可理解、可复现、可审计的输入生成六爻原始爻值，并将起卦行为与后续排盘算法清楚分离。

## 2. 模式划分

### 首版确认

- **手动模式**：用户逐爻编辑阴阳和独立动爻状态，标准化为 6/7/8/9；首版不录逐枚铜钱。
- **自动模式**：系统模拟六次三枚铜钱过程，逐次展示并记录。

### 后续候选

- 数字起卦。
- 时间起卦。
- 一次性输入六个爻值。
- 其他经评审的传统方式。

后续模式不能复用“自动摇卦”的名称；每种模式需要独立规则、输入校验和来源说明。

当前手动/自动模式均由本地 `liuyao_engine` 生成，完成后只保存一次当前快照并跳转独立卦面；自动模式不会因存档或页面跳转再次随机。

## 3. 范围内

- 占问问题、可选分类/备注、起卦时间。
- 模式选择、六次输入过程、撤销上一步、重新开始。
- 原始投掷或录入数据、最终 6/7/8/9 爻值、起卦模式版本。
- 从初爻到上爻的顺序提示。
- 提交前的完整性校验和用户确认。

## 4. 范围外

- 卦名、纳甲、六亲等排盘结果，由 SPEC-003 负责。
- 断卦建议、吉凶结论和 Agent。
- 未完成知识规格的数字或时间起卦。

## 5. 关键要求

- `FR-CST-001` 六爻的语义和起卦顺序固定为初爻到上爻；完整编辑器按传统卦面从上爻到初爻自上而下显示，并明确提示顺序差异。
- `FR-CST-002` 手动模式通过“阴阳 + 独立动爻”直接形成少阳、少阴、老阳、老阴；逐枚铜钱只属于自动模式的原始记录，不进入首版手动编辑器。
- `FR-CST-003` 自动模式保存每爻三枚铜钱的原始面值、合计与最终爻值。
- `FR-CST-004` 自动随机源及映射规则必须有版本，并可在测试环境注入固定种子或固定序列。
- `FR-CST-005` 用户可以撤销未提交的最后一爻并重摇，但提交后修改应创建新起卦版本。
- `FR-CST-006` 保存或进入卦面前显示六爻摘要并要求确认。
- `FR-CST-007` 任何模式最终都输出统一的 `CastingRecord`，排盘引擎不直接读取 UI 状态。
- `FR-CST-008` 手动模式主页面顺序采用：占问 → 日期时间 → 模式 → 六爻编辑 → 重置/排盘。
- `FR-CST-009` 每一爻由“阴阳”和“是否为动爻”两个独立状态组成；开启某爻的“动”即表示该位置是动爻，并无歧义地映射为老阴、少阳、少阴、老阳。
- `FR-CST-010` “重置”是次级操作且需要避免误触；“排盘”是唯一主提交操作，六爻不完整时不可提交。
- `FR-CST-011` 编辑过程可显示本卦/变卦预览，但预览不得替代提交前校验和最终排盘。
- `FR-CST-012` 动爻进入变卦时阴阳反转：老阴变阳、老阳变阴；静爻在变卦中保持不变。
- `FR-CST-013` 手动页初始暂设六爻均为少阳 7、均不动，对应“乾为天之乾为天”预览；该默认值为可调整的实施口径。
- `FR-CST-014` 六行在界面按上爻到初爻显示，允许任意顺序编辑；提交和持久化始终按初爻、二爻、三爻、四爻、五爻、上爻序列化。
- `FR-CST-015` “重置”恢复六个少阳 7 和全部不动，并刷新本卦/变卦预览。
- `FR-CST-016` 已被 FR-CST-024 取代：早期手动切片只预览不存档；档案边界接入后改为成功排盘即存档。
- `FR-CST-017` 手动页提交前必须展示确认层，明确显示内部记录顺序“初爻 → 上爻”和六个标准爻值；用户再次确认后才调用排盘接口。
- `FR-CST-018` 手动页首个实现暂以 `Asia/Shanghai`/UTC+08:00 生成带偏移的 RFC 3339 时间，并在界面显示“北京时间”；可选时区与换日规则继续由 Q-003 管理。
- `FR-CST-019` 自动模式首版由一次用户操作生成六爻，内部仍严格按初爻到上爻执行六次三枚铜钱投掷；结果必须逐爻展示，不能只返回最终卦名。
- `FR-CST-020` 每次自动投掷保存三个 `2/3` 数值、求和结果和标准爻值；在币面称谓来源冻结前不把 `2/3` 擅自显示为“正/反”或“字/背”。
- `FR-CST-021` 生产自动起卦使用系统随机源；固定 `seed` 只允许测试和显式调试，并在记录中标记 `seeded_test`，产品 UI 不提供 seed 输入。
- `FR-CST-022` 引擎统一输出版本化 `casting_record` 和起卦 `calculation_trace`；手动记录的 `coins=[]`，自动记录包含三枚原值，二者均按初爻到上爻排列。
- `FR-CST-023` 已被 FR-CST-024 取代：早期内联预览允许对未保存结果“重新摇卦”；自动存档后结果直接离开编辑页，无未保存覆盖态。
- `FR-CST-024` 手动确认或自动摇卦完成后，客户端必须先把当前已生成的完整快照保存为案例，再进入结果页；保存失败不得显示为已存档。
- `FR-CST-025` 排盘后必须跳转到独立卦面路由，不在手动/自动编辑页下方继续堆叠结果。

### 5.1 手动爻状态模型

| 爻形 | “动”开关 | 传统名称 | 标准爻值 | 变卦结果 |
|---|---:|---|---:|---|
| 阴爻 | 关闭 | 少阴 | 8 | 阴爻不变 |
| 阴爻 | 开启 | 老阴 / 动阴 | 6 | 变为阳爻 |
| 阳爻 | 关闭 | 少阳 | 7 | 阳爻不变 |
| 阳爻 | 开启 | 老阳 / 动阳 | 9 | 变为阴爻 |

手动编辑器必须把爻形与“动”开关作为两个明确控件。用户打开某一行的“动”后，只标记该爻为动爻，不应自动改变本卦中的阴阳；阴阳反转发生在生成变卦时。

## 6. 统一输出概念

`CastingRecord` 至少包括：模式、模式版本、开始/完成时间、时区、问题、六条爻的原始输入、标准化爻值、用户确认时间、可选随机证明字段。

## 7. UI 状态

- 未开始、进行中（1/6 至 6/6）、待确认、已提交。
- 中断后恢复、输入非法、随机服务异常、重复提交。
- 自动模式允许选择逐次展示还是连续完成，首版交互待 UI 评审。

### 7.1 手动模式参考基线

参考证据：LG-20260805-03（内部对标截图，不随开源仓库分发）。

- 采用六行直接编辑和“爻形 + 独立动静控件”的信息结构。
- 采用大卡片分组，占问和时间均在六爻编辑区之前。
- 采用“描边重置 + 实心排盘”的主次操作关系。
- 不采用参考图中的“金口诀”入口；本项目工具范围只有六爻。
- 不采用含义不明的 `132 / 3000` 文本，除非后续证据说明其价值。
- 颜色、字号、圆角和图标只作为视觉方向，须由 SPEC-007 统一定义。
- 爻形负责切换阴阳；“动”按钮独立切换该位置是否为动爻。

## 8. 验收重点

- 固定六组原始铜钱输入能得到唯一的 6/7/8/9 序列。
- 手动和自动模式产出相同结构的标准化记录。
- 重开 App 后未完成起卦是否恢复，应有一致策略。
- 测试 6、7、8、9 四种爻值均能正确产生阴阳和动静语义。
- 同一阴爻开关“动”前后分别输出 8 和 6；同一阳爻分别输出 7 和 9。
- 开启动爻不会立即改写本卦爻形，只影响动爻标记和变卦爻形。
- 任意顺序编辑后，提交记录中的数组顺序仍稳定为初爻到上爻。
- 重置后结果为 `[7, 7, 7, 7, 7, 7]`，动爻列表为空。
- 从上到下编辑“上爻阴动、初爻阳动”后，提交数组必须为 `[9, 7, 7, 7, 7, 6]`。
- 占问为空时不打开确认层、不调用本地排盘；确认层取消时也不排盘。

## 10. 当前实现状态

### 已实现

- [手动起卦页面](../../apps/mobile/lib/src/features/casting/manual_casting_page.dart)：占问、北京时间、上爻到初爻六行编辑、阴阳切换、独立动爻、重置确认和排盘前二次确认。
- [Flutter 排盘客户端](../../apps/mobile/lib/src/features/casting/casting_client.dart)：直接调用本地 `liuyao_engine`，以 `castingMethod=manual` 和初爻到上爻的六值数组生成快照。
- [排盘预览模型](../../apps/mobile/lib/src/features/casting/casting_models.dart)：只消费当前切片所需的版本、时间、爻值、本/变卦名和四柱摘要。
- 一级导航按需创建页面并使用 `IndexedStack` 保活；手动草稿在标签切换后保持，且未访问档案页时不会提前发起档案请求。
- 固定样例“上爻阴动、初爻阳动”在 Flutter、Dart 轮子和 Python golden 中均保持 `[9, 7, 7, 7, 7, 6]`，结果为“泽天夬 → 天风姤”。
- [自动铜钱页面](../../apps/mobile/lib/src/features/casting/automatic_casting_page.dart)：一次生成六爻；自动存档后，独立卦面页的“起卦记录”逐爻展示三枚 2/3、求和、传统名称、动爻状态、规则版本和随机源类型。
- [手动/自动模式容器](../../apps/mobile/lib/src/features/casting/casting_page.dart)：两个模式使用同一 `CastingDataSource`，分别保活尚未保存的页面状态。
- Python 排盘合同升级为 schema v2：新增 `casting_record`、逐爻原始输入、`random_source` 和起卦 `calculation_trace`；手动与自动使用同一结构。
- 自动模式保存六次逐枚 2/3、合计、爻值和随机源；固定 seed 仅供 Dart 测试，不作为 Python 随机序列跨语言合同。
- 手动与自动两条路径均在排盘成功后自动保存当前快照，然后跳转独立卦面页；Flutter 测试断言每次只保存一份。

### 尚未实现

- 可选时区、地点、真太阳时和最终换日口径。
