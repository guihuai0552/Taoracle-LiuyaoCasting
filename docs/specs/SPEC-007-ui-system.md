# SPEC-007 UI、导航与信息呈现

> 状态：`Implemented / Awaiting Visual Review`  
> 版本：1.9  
> 最近更新：2026-08-07  
> 依赖：UI 对标记录（内部资料，不随开源仓库分发）、全部页面 Spec

## 1. 目的

建立统一的移动端页面结构和视觉系统，使万年历、六爻卦面和档案在信息量较大时仍清楚、稳定、可扩展。

当前产品不设正式名称，文档统一使用“本产品”或“六爻排盘与存档工具”作为工作称呼；命名和品牌标识在核心功能规格稳定后另行设计。

## 2. 范围内

- 一级导航、页面层级、返回与深链规则。
- 色彩、字体、间距、圆角、边框、阴影和图标等 design tokens。
- 月历、表单、起卦过程、卦面、档案列表/详情、编辑、导出等关键页面框架。
- 加载、空、错误、禁用、选中、编辑未保存等通用状态。
- 深色模式与无障碍的版本规划。
- 用户提供参考截图中可验证的界面借鉴结论。

## 3. 范围外

- 六爻与历法算法。
- 竞品品牌资产或逐像素复制。
- 未进入对应功能 Spec 的装饰性页面。

## 4. 暂定一级导航

`万年历 / 六爻 / 档案 / 设置`

“工具”不是一个容纳多术数的市场页，因为当前工具范围只有六爻。是否把“六爻”命名为“起卦”由线框评审决定。

参考图中的底部导航是“日历 / 工具 / 档案 / 我的”。本项目确认可借鉴四项导航和固定底栏形态，但不直接确认相同命名：产品只做六爻，因此“工具”可能改为“六爻”；“我的”与“设置”的范围仍待定义。

当前实现切片暂用 `日历 / 六爻 / 档案 / 设置`，且不提供 Agent 一级入口。该顺序已可用于后续页面接入，最终文案仍允许在完整流程评审时调整。

## 5. 卦面呈现原则

- 排盘成功后进入独立卦面路由，主阅读顺序固定为：占问与时间 → 六爻主表 → 十二长生/神煞摘要 → 计算明细 → 解读 → 反馈。（2026-09-04 调整：十二长生与神煞卡移至卦面下方，用户选择截图而非导出时卦面信息居中、长生神煞在下方完整可见。）
- 本卦与变卦必须建立清晰列关系，不能让用户来回跳读。
- 动爻、世、应使用文字/符号，不只用颜色。
- 六神、伏神、六亲、纳甲和爻象在手机宽度下采用优先级布局；不得依赖横向滚动作为默认方案。
- 十二长生与神煞默认按需要展开，命中点可回链到对应爻。
- “计算明细”使用可展开步骤，不把所有公式永久堆在主卦面上。

## 6. 关键要求

- `FR-UI-001` 用户从任一一级入口最多两次主要操作到达起卦页。
- `FR-UI-002` 所有提交动作都有明确的进行中、成功和失败反馈。
- `FR-UI-003` 未保存编辑离开时必须提醒或自动保留草稿。
- `FR-UI-004` 常见 360dp 宽度下核心内容无水平溢出。
- `FR-UI-005` 术语使用统一词表，不在不同页面混用“排班/排盘”“挂/卦”等错误字样。
- `FR-UI-006` 竞品借鉴项必须关联证据编号；无证据项标为项目自主设计。
- `FR-UI-007` 页面采用浅色低对比基底、白色内容卡片和单一主强调色的方向；精确 token 必须通过对比度与真机测试确定。
- `FR-UI-008` 五行颜色只能作为辅助编码，干支、动爻、世应等信息仍需文字或符号。
- `FR-UI-009` 月历、手动起卦和卦面组件分别关联 LG-20260805-01/03/02，设计稿偏离时需记录原因。
- `FR-UI-010` 大圆角卡片用于信息分组，但不得导致有效内容宽度不足或一屏只能显示少量关键数据。
- `FR-UI-011` 手动六爻编辑器按上爻到初爻自上而下呈现，初始暂显六个少阳静爻，允许任意行编辑；界面需提示内部与传统起卦顺序为初爻到上爻。
- `FR-UI-012` 排盘编辑页不内联展示完整结果；保存成功后通过新路由打开独立卦面页，系统返回键可回到原起卦模式。
- `FR-UI-013` 独立卦面页用卡片区分占问事实、规则标注、基础卦面、解读和反馈；十二长生、神煞、计算明细、解读和反馈默认折叠。
- `FR-UI-014` 自动起卦的六次原始铜钱记录在卦面页中作为独立可展开区块，手动起卦不显示伪铜钱数据。
- `FR-UI-015` 六爻主表必须在同一视觉行对齐本伏、本卦和变卦，不再把变卦降级为本卦单元格下方的第二行辅文。
- `FR-UI-016` 木/火/土/金/水使用绿/朱砂/褐土/金褐/蓝色辅助编码；天干和地支分别取自身属性色，仍保留文字内容以满足非颜色识别。
- `FR-UI-017` 新排盘的“伏神”列必须从上爻到初爻六行全部有内容，并与同位置本卦飞神严格对齐；历史快照未保存的伏神保持空位，不用新规则补算。
- `FR-UI-018` 六神与六亲不得为节省宽度缩写成单字；四柱与对应旬空采用四列对齐的双行面板，并与本卦/变卦摘要使用相同内容宽度、底色和圆角层级。360dp 下允许单元格等比缩小，但不允许截断字段或横向滚动。
- `FR-UI-019` 卦象摘要必须同时显示伏卦名称，并标明采用本卦所属宫规则；伏神列逐爻展示该伏卦的六亲纳甲，使名称和六条明细可以相互核对。
- `FR-UI-020` schema v13 及以后新盘在六爻主表增加固定宽度的“宿”列，每爻显示一个京房配宿；卦名摘要下方显示世爻宿和64卦全局序号。宿位采用金褐色独立编码，不挤占五行色语义；旧档案没有该合同字段时整列不显示，也不补算。
- `FR-UI-021` 档案卡采用固定三块网格：左侧分类印记；右上占问事项；右下分别显示时间与“本卦 → 之卦”。整卡进入详情，不在卡内堆叠多个次操作。
- `FR-UI-022` 六爻账页中，伏神、本卦、变卦单元均采用“大主行 + 小副行”；主行承载完整六亲与纳甲，副行承载五行及长生/宿等注解。爻象、`Ｏ/Χ` 与世应居中独立占位，左右本变卦保持同行。
- `FR-UI-023` 新视觉候选采用中式窗棂网格、黑白水墨、宣纸留白和浅羊皮纸卷；纹样只用于边界与空白区，不进入高密度正文背景。朱砂只作当前、动爻、错误和主操作的小面积强调。
- `FR-UI-024` 04A 页面结构固定为“占问与时间 → 四柱旬空+本变卦+六爻账页大卡 → 十二长生摘要 → 神煞摘要”（2026-09-04 起卦面大卡在前，截图分享时卦面居中）。六爻账页内的伏神、本卦和变卦均保留主副两行；本变卦各自有爻象。
- `FR-UI-025` v0.2 视觉 token 使用宣纸 `#F5F0E6`、内容纸 `#F8F4E8`、浅羊皮纸 `#F2E8D5`、真墨 `#1C1C1C`、中墨 `#3A3A3A`、淡墨 `#D0D0D0` 和朱砂 `#B22222`。窗棂线默认透明度为 8%–12%，不铺入卦面正文。
- `FR-UI-026` 档案页右上提供独立迁移入口；操作面板必须明确批量包包含卦面快照、全部解读和反馈，并提示文件可能包含私人占问内容。
- `FR-UI-027` 导入文件选定后先展示档案、新增、相同、冲突、解读和反馈六项计数；安全合并为朱砂主操作，清空恢复为描边次操作且必须二次确认。
- `FR-UI-028` 单档导出面板同时提供 Markdown、JSON 与“卦面长图 PNG”；面板在小屏或系统字体放大时可滚动，不得底部溢出。
- `FR-UI-029` 导出面板内提供两个内容开关：「包含解读与反馈」（关闭后本次导出只含卦面与占问）与「包含解读历史版本」（初始值取首启选择或设置页默认）。首次导出前弹一次性选择框确定历史版本默认口径，选择写入偏好，之后可在设置页修改。
- `FR-UI-030` 设置页「卦面显示」分区提供「导出默认含解读历史版本」开关，与导出面板的本次开关相互独立：设置只改默认值，不强制覆盖单次选择。
- `FR-UI-031` 档案详情的「占问」文本行内提供编辑入口，与既有「编辑背景问念」并存：前者修改起卦时输入的占问文本，后者继续作为详细补充通道。
