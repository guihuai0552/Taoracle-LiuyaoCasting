# SPEC-008 二十八宿知识与入卦规格

> 状态：`Implemented Baseline / Formal Authority Pending`  
> 版本：0.6  
> 最近更新：2026-08-07  
> 依赖：[京房六十四卦配二十八宿规则](../rules/jingfang-28-mansions-rule.md)、SPEC-001、SPEC-003

## 1. 目的

为二十八宿建立不混淆、可验证的知识和数据边界。用户已提供并确认“京房六十四卦配二十八宿”首套规则；当前完成结构化合同、计算明细、逐爻 UI 和档案快照接入。

## 2. 必须先拆开的两个概念

### A. 万年历值日二十八宿

以日期或特定历法周期确定当日值宿，属于日历派生信息，未来由 SPEC-001 展示。

### B. 六爻中的二十八宿/五星入卦

将二十八宿以及可能关联的五星、建候、积算等体系映射到卦、爻或时空坐标，属于独立高阶排盘模块。

两者即使共享名称，也不能在没有来源证明时共用同一算法或字段。

## 3. 当前范围内

- 建立术语表、资料目录和来源等级。
- 列出二十八宿固定属性候选：名称、七曜、四象、方位、五行等，逐项等待来源确认。
- 定义值日宿输入/输出的规格占位。
- 定义入卦体系的输入、中间量、输出、落点和计算明细占位。
- 保存原始资料中的异名、流派和版本差异。
- 设计 golden case 模板。
- 固定 v1 入卦流程：按乾、震、坎、艮、坤、巽、离、兑的八宫顺序，从乾为天世爻参宿起连续确定 64 卦世爻宿，再按“世、应、世卦、应卦、世卦、应卦”给六爻装宿。
- 入卦结果明确落到六个单爻；完整算法、64 卦表、装配位置表和冲突见独立规则文档。

当前规则已进入独立纯 Dart 引擎，并从 schema v13 起随档案冻结。schema v16 起同一规则分别应用于本卦、完整伏卦和变卦：每层先以自身卦码确定卦宫、八宫序位和世应，再独立确定世爻宿与六爻装配；静卦不生成变卦层。五星、建候、积算仍不在本实现范围。

### 已知技术候选但尚未采用

cnlunar 提供 `get_the28Stars()`，可以作为“万年历值日二十八宿”的候选来源。它只说明某日期的值日宿能力可研究，不证明其规则适用于六爻二十八宿/五星入卦；在用户资料完成前不得把两者连接。

## 4. 当前范围外

- 将当前逐爻配宿规则解释成吉凶结论。
- 生成吉凶解释或把三层星宿合成为单一结论。
- 将网络文章或现有库中的表格未经交叉验证直接入库。
- 把“万年历值日宿”直接当作“六爻入卦结果”。

## 5. 仍待补齐的资料

1. 可定位的书名、版本、页码或原始资料影像。
2. 用户确认的三处文字纠错已完成；仍待正式文献交叉校勘。
3. 五星的定义、周期、位置或数值来源。
4. 建候、积算等术语的精确定义。
5. 至少一个跨越轸到角的完整逐爻样例。
6. 与万年历值日宿的关系和差异。
7. 卦面显示层级、解释文本和导出字段。

## 6. 暂定数据分区

```text
calendar.daily_mansion                         # 万年历值日宿；规则未定
annotations.twenty_eight_mansions              # 京房六十四卦逐爻配宿 v1
annotations.twenty_eight_mansions.line_placements[]
annotations.hexagram_layers.base.twenty_eight_mansions
annotations.hexagram_layers.hidden.twenty_eight_mansions
annotations.hexagram_layers.changed.twenty_eight_mansions  # 静卦为 null
calculation_trace[mansion.jingfang.*]           # 完整中间过程
```

入卦字段已由 schema v13 固定；万年历值日宿已作为独立 provider 字段实现，二者不能相互替代。

## 7. v1 实施状态与后续门槛

- 三项文字纠错已由用户确认，64卦和六种世爻位置已经自动测试。
- schema v13 及以后保存全部中间运算；旧档案不补算。
- UI 在本卦、伏卦、变卦纳甲副行分别显示该层逐爻宿；本卦另保留世爻宿摘要。
- 后续接入五星、建候、积算前，仍须补齐独立规则、样例和展示决定。
