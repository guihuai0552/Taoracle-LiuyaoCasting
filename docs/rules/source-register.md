# 规则来源登记表

> 状态：`Active`  
> 最近更新：2026-08-07

任何历法、六爻、神煞或二十八宿规则，在写入正式 Spec 前都必须在此登记。口传、截图和软件结果可以作为线索，但不能在没有适用范围和样例的情况下直接成为实现依据。

## 1. 来源等级

| 等级 | 定义 | 使用方式 |
|---|---|---|
| A | 可定位的经典、正式出版物、权威标准或原始规则文档 | 可作为主依据，仍需样例验证 |
| B | 有作者、版本和完整推导的专业资料 | 可作为实现依据，需与 A 或样例交叉验证 |
| C | 可重复验证的成熟软件/开源实现 | 可作对照，不自动视为规则权威 |
| D | 网络文章、论坛、短视频、无出处表格 | 仅作线索 |
| U | 用户提供且尚未完成来源说明的资料 | 先保留原样，评审后定级 |

## 2. 登记字段

每条来源必须记录：

- `source_id`：稳定编号。
- 标题、作者/整理者、版本/年代。
- 文件路径或链接、页码/章节/截图编号。
- 覆盖规则与适用流派。
- 原文摘要（避免大段复制受版权保护内容）。
- 与其他来源的冲突。
- 验证样例与结论。
- 采用状态：候选、采用、部分采用、拒绝、待确认。

## 4. 冲突处理

遇到不同来源给出不同表格或取法时：

1. 不直接选择“看起来常见”的版本。
2. 分别登记来源、输入域和结果差异。
3. 建立最小冲突样例，展示两种口径的具体输出。
4. 由用户确认采用一种、并存为规则包，或延期。
5. 结果写入决策日志；数据中保留规则版本。
