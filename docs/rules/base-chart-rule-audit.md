# 六爻基础卦面规则来源与实现审计

> 状态：`Implemented Baseline / Authority Pending`  
> 版本：1.2  
> 最近更新：2026-08-05  
> 关联：SPEC-003、Q-003、Q-008、DEC-023、DEC-036、SRC-019

## 1. 本轮结论

基础卦面首个可执行规则包固定为 `liuyao.base.najia_2_0_1_compat.v1`。它复现 `najia==2.0.1` 的纳甲、八宫世应、六亲和六神表，同时把第三方库原先的拼接字符串拆成稳定字段，并为每一步生成计算明细。伏卦不再沿用上游 `hide.seat`：规则包 1.3.0 根据 DEC-036 和 SRC-019，按内外卦“相同取宫卦错卦、不同取宫卦”独立生成完整伏卦。

这是一套**已固定、可回归的工程基线**，不是对传统流派权威性的最终结论。后续获得可定位的正式文献后，必须先建立冲突样例，再决定保持兼容包、升级规则包或并存多个规则包；不得静默改写历史卦面。

## 4. 固定规则

### 4.1 卦码与变爻

- 六位卦码从左到右对应初爻至上爻。
- 阳为 `1`，阴为 `0`。
- 6、9 为动爻；变卦只反转动爻阴阳。
- 本卦与变卦均保存稳定 code，卦名使用 Najia v2.0.1 的 64 卦表。

### 4.2 纳甲表

| 卦 | 内卦三爻 | 外卦三爻 |
|---|---|---|
| 乾 | 甲子、甲寅、甲辰 | 壬午、壬申、壬戌 |
| 兑 | 丁巳、丁卯、丁丑 | 丁亥、丁酉、丁未 |
| 离 | 己卯、己丑、己亥 | 己酉、己未、己巳 |
| 震 | 庚子、庚寅、庚辰 | 庚午、庚申、庚戌 |
| 巽 | 辛丑、辛亥、辛酉 | 辛未、辛巳、辛卯 |
| 坎 | 戊寅、戊辰、戊午 | 戊申、戊戌、戊子 |
| 艮 | 丙辰、丙午、丙申 | 丙戌、丙子、丙寅 |
| 坤 | 乙未、乙巳、乙卯 | 癸丑、癸亥、癸酉 |

地支五行固定为：亥子水、寅卯木、巳午火、申酉金、辰戌丑未土。

### 4.2.1 八宫卦序

`palace_sequence` 的业务含义固定为八宫内的 1–8 序位：本宫纯卦 1、初世卦 2、二世卦 3、三世卦 4、四世卦 5、五世卦 6、游魂卦 7、归魂卦 8。

engine `0.10.0` 及更早的 schema v3–v10 快照曾将世爻位置误写入同名字段，不能按新语义直接展示。engine `0.10.1` / 基础规则包 `1.1.0` 起纠正字段并为变卦增加同样序位。旧案不重算、不改写，UI 明确显示“序位未记录”。固定验收样例为：山天大畜/艮宫·3 → 山泽损/艮宫·4。

### 4.3 六亲

六亲只以本卦宫五行作为“我”，逐爻五行作为“他”：同我为兄弟，我生为子孙，我克为妻财，生我为父母，克我为官鬼。变卦各爻仍以本卦宫五行为基准。

### 4.4 六神

初爻起神固定为：甲乙青龙、丙丁朱雀、戊勾陈、己螣蛇、庚辛白虎、壬癸玄武；之后按青龙、朱雀、勾陈、螣蛇、白虎、玄武顺序从初爻排至上爻。

日干来自项目 `cnlunar==0.2.0` 时间适配层，不读取 Najia 内部历法结果。这样万年历与卦面只保留一套时间上下文。

### 4.4.1 四柱旬空

engine `0.11.0` / schema v11 起，对项目 cnlunar 生成的年、月、日、时四柱分别执行同一旬空函数，而不再只保存日柱旬空。合同在 `time.pillar_voids.year/month/day/hour` 下分别保存两字旬空及两个地支数组；原有 `day_void` 与 `day_void_branches` 保留为兼容字段。

固定验收时刻 `2026-08-04 22:22:29 +08:00` 的四柱为丙午、乙未、庚戌、丁亥，对应旬空依次为寅卯、辰巳、寅卯、午未。历史快照缺失逐柱旬空时不反向补算。

### 4.5 伏神

完整规则见 [`fu-gua-rule.md`](fu-gua-rule.md)。先取得本卦所属宫经卦和其错卦；本卦内卦或外卦与宫卦相同则取错卦，不同则取宫卦，所得伏内卦和伏外卦组合为完整伏卦。伏卦按自身内外卦纳甲，六亲仍以本卦宫五行为基准，六条结果逐位绑定本卦飞神。

engine `0.10.2` / 规则包 `1.2.0` 曾把本宫纯卦六爻直接当作全部伏神，该临时口径已被 DEC-036 取代。engine `0.12.0` / schema v12 / 规则包 `1.3.0` 起保存完整伏卦、内外比较结果和六条伏神。所有历史快照仍原样显示，不用新规则静默重算。

## 5. 已发现偏差与处理

### 5.1 旧字段拆分错误

旧适配器将 `甲子水` 取前两字写入名为 `branch` 的字段，实际得到的是干支；下游旺衰代码又把首字当地支，造成地支错位。本规则包不兼容这个错误字段语义：schema v3 起 `branch/earthly_branch` 都只能是单个地支，另设 `heavenly_stem` 与 `gan_zhi`。

### 5.2 两套历法冲突

固定样例显示 Najia 内部 `lunar_python` 与 cnlunar 在边界时刻可能不同：

| 时间（Asia/Shanghai） | cnlunar 四柱 | Najia 内部四柱 | 影响 |
|---|---|---|---|
| 2026-02-07 12:16 | 乙巳/庚寅/壬子/丙午 | 丙午/庚寅/壬子/丙午 | 年柱不同 |
| 2026-02-04 00:30 | 乙巳/庚寅/己酉/甲子 | 乙巳/己丑/己酉/甲子 | 月柱不同 |
| 2026-02-04 23:30 | 乙巳/庚寅/庚戌/丙子 | 丙午/庚寅/己酉/丙子 | 年柱、日柱不同，六神会不同 |

当前工程口径：四柱、旬空与六神日干统一由 cnlunar 适配层生成；边界流派最终选择仍由 Q-003 跟踪，返回值必须暴露 `time.rule_status=provisional`。

### 5.3 上游测试不足

Najia v2.0.1 自带测试覆盖少数函数和样例，没有覆盖完整 64 卦、全部世应类型或伏神分布。本项目补充：64 卦结构不变量、固定静卦、固定多动含伏神、十日干六神起例、时间边界差异保护和 API 合同测试。

## 6. schema v3 兼容策略

- schema v1/v2 历史 `chart_json` 保持原样，不迁移、不静默重算。
- schema v3 新增 `rule_package`、结构化时间柱、卦码/上下卦、独立纳甲字段、稳定爻 ID和模块化 trace。
- `raw_najia` 仅保留为诊断快照，不再作为 UI、存档检索或后续规则的业务输入。
- 若未来采用新权威表，发布新的规则包 ID；历史案例继续显示原规则包。
