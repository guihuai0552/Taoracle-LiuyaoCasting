# ADR-0001：采用文档优先与单一事实源

> 状态：`Accepted`  
> 日期：2026-08-05

## 背景

本产品同时涉及历法、六爻多层规则、移动端密集信息展示、历史档案和后续二十八宿体系。若直接开发，容易出现术语混用、不同端重复算法、规则无出处以及历史结果被新版本覆盖的问题。

## 决定

1. `docs/README.md` 是项目上下文总入口。
2. 所有功能先有独立 Spec；状态达到 `Ready` 后才能进入正式开发。
3. 聊天中的结论必须回写文档，聊天本身不作为长期事实源。
4. 每项传统规则必须有来源编号、规则版本和固定样例。
5. 代码实现若与 Spec 不一致，先更新并评审文档，或将代码视为偏差修复。
6. 当前不开发 Agent；先完成万年历、六爻工具和档案基础。

## 影响

- 前期会投入更多时间整理规则和验收样例。
- 开发任务可以按 Spec 独立排期，减少跨模块返工。
- 规则升级和历史档案兼容有明确依据。
- 用户需要参与关键口径和 UI 证据的确认。

## 执行方式

- 每次工作结束至少更新：相关 Spec、问题/决定台账、变更日志。
- 实施中发现规则或交互需要调整时，在同一个工作节点实时回写文档，不把文档补录推迟到功能完成之后。
- 每周或每个阶段做一次文档一致性检查。
- 只有在依赖问题关闭后，Spec 才能进入 `In Review`。
