## 1. 目的与范围

本文档把用户提出的八项需求拆解为可验证的工程方案，并记录历法事实核查基线与
2026-08-09 日柱错位问题的根因。执行顺序与验收标准均以此为准。

八项需求：

1. 修复动爻出现时爻线长短不一的问题
2. 十二长生默认按日柱显示，可在十二长生表点选年柱/月柱/日柱/时柱/五行后卦面联动刷新；卦面小字可切换为五星
3. 解释「受气」「化绝」的一体两面
4. 六爻档案的「背景问念」支持后续补充修改
5. 万年历支持快速翻到指定年月；起卦日期选择中文化；在万年历点选日期后到起卦页自动带入该日期
6. 重点：交月按进入当月节气的子时交；交日按前一天 23:00:00.001 进入当日子时（日柱按第二天算），不按天文授时具体时刻；两种口径可主动选择

8. 增加手动填写四柱

重大 bug：万年历甲子历日子整体错位一天。2026-08-09 应为农历六月廿七、乙卯日，但此前万年历网格显示甲寅日。

## 3. 日柱整体错位一天：根因与修复

### 3.1 复现案例

- 万年历网格（`apps/mobile/lib/src/features/almanac/almanac_client.dart`）逐日调用
  `engine.calculateDayGanzhi(DateTime(year, month, day))`，传入的是**本地时区 DateTime**。
- `calculateDayGanzhi` 内部执行 `date.difference(baseDate).inDays`，其中 baseDate 是
  `DateTime.utc(1900, 1, 31)`。
- Dart 对 `isUtc=false` 的本地 DateTime 做 `difference` 时会先按 UTC 换算：在 UTC+8
  设备上，本地 2026-08-09 午夜 = UTC 2026-08-08 16:00，与 UTC 基准的整天数少 1，
  `inDays` 截断后少算 1 天 → 日柱整体提前一天（乙卯→甲寅）。

### 3.2 根因结论

1. **主根因**：`calculateDayGanzhi` 未对输入 DateTime 做墙上时间归一化，把本地时间
   直接当 UTC 容器做 `difference`，在 UTC+8 设备上产生系统性 -1 天偏移。
   - `solarToLunar`、`isDateSupported` 等函数内部已用 `DateTime.utc(y, m, d)` 重建容器规避，
     `calculateDayGanzhi` 未做同样处理，是唯一漏网点。
2. 注释「1900-01-31 = 甲子日」错误（实际为甲辰日），会误导后续维护。

### 3.3 修复内容（已完成）

- `packages/liuyao_engine/lib/src/almanac.dart`：
  - `calculateDayGanzhi` 内部先重建 `DateTime.utc(y, m, d, h, min, s, ms, µs)` 再求差值，
    无论传入本地还是 UTC 对象，均按上海墙上时间语义处理；同时修正注释。
  - 新增交日、交月策略常量与 `solarTermZiHourBoundary` 辅助函数。
  - `calculateExactJieContext` 新增 `monthBoundary` 参数（子时换月 / 精确时刻换月）。
  - `calculateAlmanac` 新增 `dayBoundary` / `monthBoundary` 参数透传，并输出
    `calendar_policy` 与 trace 选项。
- 新增测试（`packages/liuyao_engine/test/engine_test.dart`）：
  - 黄金案例 2026-08-09 = 六月廿七、乙卯日，连续序列 08-07~08-10。
  - 本地 DateTime 直调 `calculateDayGanzhi` 不错位回归。
  - 交日 23:00:00.000 / .001 边界与子正 0 点口径。
  - 交月立秋前一天 23:00:00.001 子时换月。

## 4. 交日、交月策略设计

### 4.1 概念分离

```text
civilDate        用户选择与看到的公历日期
wallClock        统一换算为上海墙上时间的计算容器
dayPillar        按交日策略计算的日柱
monthPillar      按交月策略计算的月柱
```

规则层统一使用「上海墙上时间」语义；设备时区不影响排盘。

### 4.2 交日策略

| 策略 | 标识 | 语义 |
|---|---|---|
| 民用过23点（默认，用户指定） | `civil_23_next_day` | 时刻过 23:00:00.000 整点（即 23:00:00.001 起）进入当日子时，日柱按次日算；23:00:00.000 整点仍属当日 |
| 子正0点换日 | `astronomical_midnight` | 0 点换日，23:00–23:59 夜子时用当日日柱 |

### 4.3 交月策略

| 策略 | 标识 | 语义 |
|---|---|---|
| 节气子时换月（默认，用户指定） | `solar_term_zi_hour` | 进入当月节气的子时即换月；子时按 23:00:00.001 换日规则，即节气日的前一天 23:00:00.001 起已属该节气月。年柱同步以立春子时换年 |
| 天文精确时刻换月 | `astronomical_moment` | 按节气天文精确时刻切换月柱（lunar_python 1.4.8 口径），年柱以立春精确时刻为界 |

### 4.4 历史档案兼容

档案保存当时的 `day_boundary` / `month_boundary` / `timezone` / `four_pillars_source`，
不允许历史档案随全局设置变化而被无提示重算。

## 5. 八项需求 scope 拆解

### 5.1 动爻爻线长短不一

- 现状：`chart_preview.dart` 中动爻仅改变行背景色并在爻线右侧追加 `Ｏ`/`Χ` 文字；
  `_TraditionalYaoGlyph` 内 `Row(Expanded(爻线) + 标记文字)` 导致带标记的爻线被
  压缩，`Ｏ`（老阳）与 `Χ`（老阴）宽度不一致 → 爻线长短不一。
- 方案：把动爻标记改为**固定宽度、不参与爻线布局**的叠加元素，爻线统一撑满
  逻辑宽度（46），阴阳爻同宽、间距统一；本卦/变卦/伏卦各列对齐。
- 验收：任意动爻组合下六爻线视觉等长；小屏无挤压跳动。

### 5.2 十二长生可点选参照并联动，可切换五星

- 现状：卦面小字与十二长生表均只取 `reference == 'day'`（日柱），纯展示无交互。
- 方案：
  - 新增显示模式 `annotation_mode`：`twelve_growth`（默认）/ `five_stars_jingfang`。
  - 新增参照选择 `growth_reference`：`year_pillar` / `month_pillar` / `day_pillar` /
    `hour_pillar` / `element:木火土金水`。
  - 十二长生表头可点选，点选后重算六爻 `pillarResults[reference].stage` 并刷新卦面
    小字，高亮当前选择，配置随档案保存。
  - 五星显示不再采用未经确认的“二十八宿七曜映射”假设，改按用户 2026-08-19 提供的
    **京房八宫六十四卦五星排布规则**实现；二十八宿仍作为独立标注，不被五星覆盖。
- 验收：默认日柱；切换年/月/日/时/五行后卦面即时刷新；重启不丢失；旧档案兼容。

### 5.3 受气 / 化绝的一体两面

- 定义（引擎既有规则）：五行十二长生标准表用「绝」；四土（丑辰未戌）采用《五行大义》
  四土独立表，其中「受气」即该表对「绝」位相的原始命名（如丑土在巳/午为受气）。
- 方案：在十二长生表与卦面对「受气」显示同源解释文案：「受气 = 四土独立表中『绝』的
  异名，表示气机将尽而待生」，并展示 source_phases → display_phases 映射链。
- 验收：同一爻不再出现无解释的矛盾标签；点击可查看计算依据。

### 5.4 档案背景问念后续可编辑

- 现状：`question` 只读，无编辑入口；存档在 `saveCast` 写入 `question` 字段。
- 方案：新增 `question_context`（可空长文本，可换行）与 `question_context_updated_at`；
  详情页 `_QuestionCard` 增加「编辑」入口（查看/编辑/取消/保存）；不改原卦象、四柱、
  起卦时间；旧档案空值可编辑。
- 验收：已有档案可编辑背景问念，重开保留，不影响其他字段。

### 5.5 万年历：快速翻年月 + 中文化 + 日期联动起卦页

- 现状：仅左右箭头逐月切换，无年月选择器；Material 日期组件缺中文 locale；
  万年历点击日期只更新本页，与起卦页无共享状态。
- 方案：
  - 万年历头部新增年月选择器（年份输入/滚轮 + 月份快速选择 + 「回到今天」）。
  - `MaterialApp` 配置 `flutter_localizations` 中文 locale，起卦日期选择全中文化。
  - 新增共享「起卦草稿」：万年历点选日期写入草稿，切换到起卦页时自动带入该日期
    （通过 `HomeShell` 把 `initialDateTime` 注入 `CastingPage`）。
- 验收：可快速跳任意支持年月；跳转后农历/干支/节气正确；万年历选 2026-08-09 后起卦页
  日期自动变为该日期且无偏移。

### 5.6 时刻起卦法

- 方案：`cast_engine.dart` 新增起卦方法注册机制；`time_pillar` 法按起卦时刻四柱取数
  起卦，保存方法标识与原始输入；起卦页提供方法选择。
- 验收：可独立选择；相同输入结果稳定；可保存恢复；不改变已有起卦法结果。

### 5.7 手动填写四柱

- 方案：新增 `four_pillars_source`：`calculated`（默认）/ `manual`。手动模式填写完整
  四柱（年/月/日/时，每柱天干+地支），与自动计算并存不覆盖；提供「恢复自动计算」；
  校验非法干支组合。
- 验收：手动四柱可保存恢复；修改日期时间不覆盖手动值；档案明确记录四柱来源。

## 8. 京房五星规则（2026-08-19 用户确认，进入实现）

本节取代此前“五星规则无底本、暂停”的状态。用户已明确五星名称、八宫顺序、世爻起星和卦内循环排布；本规则按用户确认口径工程化，不把五星与二十八宿七曜属性混同。

### 8.1 五星固定顺序

```text
镇土星 → 太白金星 → 太阴水星 → 岁木星 → 荧惑火星 → 回到镇土星
```

八宫顺序固定为：

```text
乾 → 震 → 坎 → 艮 → 坤 → 巽 → 离 → 兑
```

乾宫首卦乾为天的世爻起镇土星。下一宫首卦沿八宫顺序取上一宫首卦的克制星；用户给出的校验例为：岁木星克镇土星。因此实现必须保存“上一宫起星、克制关系、下一宫起星”的计算轨迹，不允许只在 UI 写死名称。

### 8.2 卦内六爻排布

以世爻为起点，按初爻到上爻的循环方向依次排入五星；世爻为第一位，之后每一爻顺推一星，五颗星循环。六爻因此使世爻的下一轮位置再次得到同一颗星。世爻与应爻相隔三位，应爻显示为世爻的克制星。

乾为天固定样例：世爻在上爻，排布为：

```text
上爻：镇土星（世）
初爻：太白金星
二爻：太阴水星
三爻：岁木星（应）
四爻：荧惑火星
五爻：镇土星
```

### 8.3 数据合同和边界

五星结果独立存放，不覆盖 `annotations.twenty_eight_mansions`：

```text
annotations.five_stars {
  rule_id: liuyao.five_stars.jingfang.v1
  palace_order_index
  palace_name
  world_line_position
  world_line_star
  line_placements[] { line_position, star, sequence_index, role }
  trace[]
}
```

本轮只实现五星排布和可追溯解释，不扩展建候、积算或吉凶判断；二十八宿仍按现有规则独立计算。若“克制星”的完整八宫首卦名称与文字例示存在歧义，以用户后续完整例盘冻结为测试夹具，不能静默猜测。

### 8.4 首批验收样例

1. 乾为天：上爻镇土、初爻太白、二爻太阴、三爻岁木、四爻荧惑、五爻镇土。
2. 每一卦从世爻开始按五星循环，世爻后一轮位置与世爻同星。
3. 世爻与应爻间隔三位，并按用户确认的克制关系输出。
4. 八宫首卦按乾、震、坎、艮、坤、巽、离、兑顺序保存起星推导轨迹。
