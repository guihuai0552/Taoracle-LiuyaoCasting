# 六爻档案迁移格式 v1

> 状态：`Implemented`  
> 最近更新：2026-08-07  
> 决策：DEC-047

## 1. 用途与保证

迁移包用于用户主动把本机档案移动到另一台设备，或在卸载前做离线备份。它不是云同步协议。每条案例都保存原始起卦、完整卦面快照、规则版本与计算轨迹、全部解读版本和全部反馈；导入不得用当前引擎重算历史快照。

文件编码固定为 UTF-8，可带 UTF-8 BOM；当前大小上限为 64 MB，扩展名为 `.json`。

## 2. 根对象

```json
{
  "format": "liuyao_archive_transfer",
  "schema_version": 1,
  "exported_at": "2026-08-07T01:23:45.000Z",
  "case_count": 1,
  "includes": ["chart", "analyses", "feedbacks"],
  "cases": [
    {
      "id": "case-...",
      "title": "占问标题",
      "question": "占问内容",
      "chart": {},
      "analyses": [],
      "feedbacks": []
    }
  ]
}
```

`cases` 中的每个对象使用 SPEC-005 当前完整 `CaseDetail` 合同。示例省略的字段不是可选字段；实际导出必须保留原对象全部字段。

## 3. 导入校验

写入前依次校验：

1. 文件不超过 64 MB，并能以严格 UTF-8 解码。
2. 根节点是 JSON 对象，`format` 与 `schema_version` 受支持。
3. `cases` 是数组，且 `case_count` 与实际长度一致。
4. 每条记录能构造完整 `CaseDetail`，ID 非空且包内不重复。
5. 全部校验通过后才允许合并或替换；任一步失败都不修改本机档案。

为便于从旧版本恢复，导入器还兼容既有单档 JSON 和本地 schema v1 容器，但新的批量导出只生成本文格式。

## 4. 冲突策略

- 新 ID：直接导入。
- 同 ID 且内容完全相同：跳过。
- 同 ID 但内容不同：安全合并生成新 ID，标题追加“（导入副本）”，不覆盖两边任一版本。
- 清空恢复：删除本机集合后载入迁移包，只能在预检页经第二次明确确认执行。

落盘沿用 App 私有 Documents 目录的临时文件原子替换；持久化失败时恢复导入前的内存状态。

## 5. 版本演进

`schema_version` 发生不兼容变更时递增。读取器不得猜测未知版本；应提示用户使用支持该版本的应用。新增可忽略元数据可在保持 v1 的情况下加入，但不得改变现有字段含义或默认丢弃解读、反馈。

## 6. 隐私

迁移包可能包含私人占问、解读和反馈。应用只在本机生成和读取文件，不自动上传；用户应通过可信渠道传输并妥善保管。匿名导出不属于 v1。
